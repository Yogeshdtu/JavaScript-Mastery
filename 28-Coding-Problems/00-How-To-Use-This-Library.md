## The Golden Rule

**Solutions dekhne se pehle, kam se kam 15-20 minutes khud try karo.** Passive reading se retention bahut kam hoti hai — struggle karna (chahe fail bhi ho) learning ka core part hai.

## How Each Problem is Formatted

```markdown
### Problem N: Title
**Difficulty:** 🟢/🟡/🔴
**Concepts Tested:** [relevant modules]
**Problem:** [description]
**Expected Approach:** [hints, without giving away the full solution]
```

## Suggested Workflow

1. Complete a theory-module (01-26).
2. Come here, solve the corresponding-difficulty problems for that topic.
3. Attempt every problem in your own editor/console — don't just read and nod.
4. Compare with the Solutions folder — note differences in approach, not just correctness.
5. For Output-Prediction problems (Module 05), always predict FIRST, then run the code to verify.

## Difficulty Guide

- 🟢 **Beginner:** Modules 01-07 concepts
- 🟡 **Intermediate:** Modules 06-14 concepts
- 🔴 **Advanced:** Modules 08-25 concepts (closures, async, prototypes, patterns)
- **Debugging:** Find and fix an intentional bug
- **Output-Prediction:** Predict console output before running
- **Interview-Level:** Common questions asked in real technical interviews
- **Real-World:** Problems modeled on actual production scenarios
